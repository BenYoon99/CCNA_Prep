이더넷 랜스위칭

-----------------
📝 [최종 검수 완료: 노트 기재용]
[1. 기본 용어 및 주소 체계]

f0/1: Fast Ethernet(f) / 0번 모듈 / 1번 포트(물리적 입구).

Interface: 포트(Port)와 같은 의미.

MAC 주소: 48bits(6bytes). 물리적 주소.

OUI: MAC 주소의 앞 절반(24비트) = 제조사 정보.

Preamble: 수신 측 클럭 동기화 제공(이더넷 프레임의 시작).

MAC Table = CAM Table: 스위치의 목적지 주소록.

[2. 스위치의 동작 원리]

학습(Learning): 프레임 수신 시, 송신자(Src MAC)와 포트를 MAC 테이블에 기록.

전달(Forwarding/Flooding):

Known Unicast: MAC 테이블 조회 -> 해당 포트로만 전달.

Unknown Unicast: 목적지 모름 -> 송신 포트 제외 모든 포트로 플러딩.

Broadcast: 목적지가 '전체' -> 송신 포트 제외 모든 포트로 플러딩.

[3. 멀티캐스트(Multicast) 처리 방식]

기본(기능 OFF): 송신 포트 제외 모든 포트로 플러딩 (브로드캐스트와 동일 취급).

고급(IGMP Snooping ON): 그룹 정보를 학습하여, 멤버 포트로만 선별적 전달(Forwarding).

64바이트 보다 작은 프레임 == runt 프레임
프레임이 64바이트 보다 작으면 padding을 사용해서 0값을 채워 64바이트로 자동으로 채워만들어준다.

1. 왜 런트(Runt)가 발생하는가? (범인: 충돌!)
네, 원래는 프레임이 64바이트보다 작으면 장비가 자동으로 패딩(Padding)이라는 0(Zero) 값을 채워서 64바이트로 만들어 보냅니다. 그런데도 런트가 찍히는 이유는 전송 도중에 데이터가 '잘려나갔기' 때문입니다.

충돌(Collision): 하프 듀플렉스 환경에서 데이터를 보내던 중 다른 신호와 충돌하면, 데이터의 중간이 찢어지거나 아예 파괴됩니다.

프레임 붕괴: 충돌이 나면 전송하던 프레임이 도착지까지 온전하게 전달되지 못하고 데이터의 일부분만 '툭' 끊겨서 전달됩니다.

결과: 받는 쪽 장비 입장에선 64바이트가 되어야 할 데이터가 30바이트, 40바이트밖에 안 들어오니 "어? 이거 최소 규격 미달인데?"라고 판단해서 Runt 에러 카운트를 올리는 것입니다.

즉, 런트는 "상대방이 작게 보낸 게 아니라, 오는 도중에 찢어진 것"입니다.

1519바이트부터 우리가 설정한 MTU 한계값(보통 1518)을 넘어서는 순간부터 'Giant'라고 부르고 에러 처리를 하는 겁니다.

정상: 64 ~ 1518 바이트.

Runt (에러): 64 바이트 미만. (주로 듀플렉스 불일치/충돌 때문)

Giant (에러): MTU 초과. (주로 MTU 설정 불일치/점보 프레임 때문)

CRC (에러) : 데이터오염 ( 주로 원인은 케이블불량이거나 노이즈떄문)

CRC 체크: 순환 중복검사 : 데이터가 오며 깨지지 않았는지 확인하는 검수/검수도장

라우팅


. C (Connected)
의미: "직접 연결된 네트워크(Directly Connected Network)"

뜻: 내 인터페이스에 IP가 설정되어 있고, 그 인터페이스에 케이블이 꽂혀서 통신 가능한 상태인 '동네 전체'를 의미합니다.

예시: C 192.168.1.0/24 is directly connected, GigabitEthernet0/0

해석: "192.168.1.0이라는 동네(네트워크)는 내 기가비트 이더넷 0/0 포트에 직접 붙어 있어!"

2. L (Local)
의미: "로컬 IP (Local IP Address)"

뜻: 그 네트워크 중에서 '내 장비가 사용하고 있는 정확한 내 IP 주소'를 의미합니다.

예시: L 192.168.1.1/32 is connected, GigabitEthernet0/0

그럼 궁금한건 스위치는 프레임이 오고가야 정보가 맥테이블에 저장되는데
라우터도 라우팅테이블에 정보저장하려면 패킷이 도착해야 되는거야?

1. 스위치 (MAC 테이블): "수동적 학습 (Passive Learning)"
스위치는 패킷(프레임)을 직접 받아봐야 압니다.

스위치는 처음에 아무것도 모르는 '백지상태'입니다. 프레임이 들어오면 "어? 이 출발지 MAC 주소가 AA:BB:CC네? 그럼 이 포트에 AA:BB:CC가 있구나!" 하고 나중에 기록합니다.

그래서 처음 통신할 때는 모르는 주소로 데이터를 보낼 때 모든 포트로 뿌리는 '플러딩(Flooding)'이 일어납니다.

2. 라우터 (라우팅 테이블): "능동적 학습 (Active/Static Learning)"
라우터는 패킷이 도착하기 전에 이미 '지도'를 가지고 있습니다.

라우팅 테이블은 데이터가 오고 가는 과정에서 채워지는 게 아니라, 사전에 정의되거나 다른 라우터들과 대화를 통해 미리 그려집니다.

라우터가 정보를 저장(학습)하는 3가지 방법은 다음과 같습니다:

Directly Connected (C): 인터페이스에 IP를 설정하고 'No Shutdown(활성화)'을 하는 순간, 라우터는 "아, 이 네트워크는 나랑 바로 붙어있구나!" 하고 즉시 생성합니다. (패킷이 오기도 전입니다.)

Static Route (S): 관리자가 직접 "저 동네로 가려면 이쪽 라우터로 보내"라고 명령어를 입력합니다.

Dynamic Routing (RIP, OSPF 등): 라우터들끼리 "나는 이런 동네들을 알고 있어, 너는?" 하고 서로 정보를 교환(라우팅 프로토콜)하여 미리 지도를 완성합니다.
